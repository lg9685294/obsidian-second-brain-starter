# 搭建结构

## 把习惯变成设计依据

| 已有习惯或痛点 | 搭建时落实什么 |
| --- | --- |
| 喜欢每天总结，又希望以后按问题调用 | Calendar 留日期原稿，Atlas 提炼主题知识，Efforts 连接具体项目 |
| 目录太多容易迷糊 | 采用中文用途名，每层一份“本层说明”，首页保留四个日常入口 |
| 开会面对空白页不知写什么 | 场景表单按“讨论、已确认、下一步”等具体问题收集信息，支持草稿和附件 |
| 收藏图和网页后想不起来 | 保存出处、内容要点、收藏理由、适用任务，再接到主题与项目 |
| 想问某个知识点在哪段课程 | 课程来源索引连接原片、转写、主题和相对原片的起止时间 |
| 下载目录堆着重复的设计文件 | 成果卡记预览、原位置、版本、用途、采用情况与依赖 |
| 换聊天后重讲一遍 | 保存目标、已确认决定、文件位置、完成程度和下一步，供新助手读取 |

根据用户需求启用模块。没有课程或成果文件时先留模板即可，不需要制造内容填满目录。

## 默认目录

```text
我的第二大脑/
├── 首页.md                         四个日常入口
├── 目录说明.md                     各层怎样用
├── AGENTS.md                       AI 从哪里读起
├── +（收集箱）/                    尚未整理与填写入口
├── Atlas（知识地图）/
│   ├── Maps（主题导航）/           按问题找资料
│   ├── Dots（知识卡片）/           能重复使用的方法
│   ├── Sources（参考来源）/        网页、课程与引用依据
│   └── Assets（成果卡片）/         预览、版本与原文件入口
├── Calendar（日历记录）/
│   ├── Notes（每日记录）/          原始记录和表单内容
│   └── Reviews（回顾总结）/        日、周等阶段回顾
├── Efforts（项目行动）/
│   └── On（正在推进）/             当前目标、决定和下一步
└── x（系统支持）/
    ├── Templates（笔记模板）/
    ├── Attachments（图片与素材）/
    ├── Rules（协作规则）/
    └── Logs（维护记录）/
```

这是参考 ACE 思路编写的中文实现，不是 Ideaverse 官方付费模板的复制。每个生成的子目录都应有说明或明确入口；空的复杂分支可以暂缓。

已有库先做目录映射，再增补缺少的入口与模板。不要因为路径不同迁移整库。修改现有笔记前保存可恢复版本；只改本次任务涉及的配置，不替换整个 `.obsidian` 文件夹。

## 组件如何组合

- **Skill**：决定如何搭建、接入什么、怎样验证；不会自己赋予文件访问权限。
- **种子库**：首页、中文目录、规则、模板和虚构示例，可复制到独立新目录。
- **本地表单**：可选录入界面。固定的保存路径见插件 README；安装文件与实际启用分开记录。
- **Bases**：可选成果卡片与记录筛选视图。关闭时仍能读 Markdown 笔记。
- **AI 文件工具**：在用户提供路径和授权后读取、关联和更新笔记。没有文件工具时先交付文件包，再由用户保存。
- **转写与跨聊天工具**：按材料另行接入；它们不是 Skill 或表单自带能力。

## 建库记录

在 Rules 中新增“搭建说明.md”，写实际使用的目录映射、时区依据、启用的入口、已有资料样本、验证结果、待配置事项和原件存放约定。不要把机器上的个人绝对路径写进公开分享包。

种子中的 `is_example: true` 只用于演示。导入真实内容时排除示例，不把演示中的决定、课程时间或成果当成用户事实。
