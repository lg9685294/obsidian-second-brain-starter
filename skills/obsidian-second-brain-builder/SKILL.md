# 搭建个人知识库

把用户的日常记录、参考资料、课程与成果，组织成能按问题找回的本地 Obsidian 库。交付可打开的文件、明确的录入入口和经过检查的检索示例。用户的明确要求优先于本 skill 的默认结构。

## 先确定搭建范围

从当前对话提取用途、使用习惯、已有资料和工具条件。通常只需明确目标文件夹，以及新建还是补充已有库；已知信息不重复询问。位置未定时可先制作独立预览包。

- **新库**：默认使用附带的中文 ACE 结构；先建立可用的小库，再接入真实资料。
- **已有库**：先读取其 `AGENTS.md`、首页和相关规则，抽样查看目录、属性与链接。提出最小增补映射，保留原命名与配置；不要把新模板整库覆盖进去。
- **只要方案或预览**：在独立交付目录生成材料。不要因此写入用户的正式库、启用插件或发布内容。

先读 [搭建结构](references/build-guide.md)。处理真实资料时再读 [资料接入](references/materials.md)，交付前读 [验收](references/acceptance.md)。

## 建立入口与规则

1. 依据用户习惯确定目录。默认用 `+（收集箱）`、`Atlas（知识地图）`、`Calendar（日历记录）`、`Efforts（项目行动）`、`x（系统支持）`。每层保留简短中文说明，首页只突出“记一笔、找知识、看项目、找成果”四个入口。
2. 保存按日期的原始记录，并用链接关联主题知识与项目。可复用知识不只埋在某天的总结中；同一来源保留一份，多处引用。
3. 将实际路径映射、时区、处理范围和协作约定写入库内规则，让后续 AI 按需读取。分别保留用户原话、用户决定、AI 建议和验证结果。
4. 默认使用本地 Markdown、附件与 Obsidian 核心功能。只有需要封面筛选时才配置 Bases；没有必要先搭向量数据库或堆砌插件。

新库可复用 [种子库](assets/starter-vault/首页.md)，用下面的辅助脚本检查后创建。`--target` 替换为已经确定并获准写入的位置。

```sh
python3 scripts/bootstrap_vault.py --target "目标文件夹"
python3 scripts/bootstrap_vault.py --target "目标文件夹" --apply
```

脚本默认只报告计划；`--apply` 只向不存在或空的目标目录创建文件。它拒绝覆盖已有库，不负责合并。缺少 Python 时，用可用文件工具完成等价的逐项检查与复制。

## 配置录入界面

根据实际记录场景选择表单或模板。用户容易面对空白页不知写什么时，优先提供会议、课堂、网页、灵感、项目五种场景，字段给出具体问题，文字、图片与文件各有入口。

需要表单时先读 [表单源码说明](assets/form-plugin/README.md)。附带插件是桌面 Obsidian 本地插件，保存普通 Markdown 和附件，没有 AI 接口。创建新库时加 `--stage-form` 只放置运行文件，**不会启用插件或改变受限模式**。插件启用按用户授权和实际工具能力完成，并用试填记录验证。

附带表单固定使用中文 ACE 路径。已有库采用其他目录时，先适配插件路径与项目筛选并检查保存结果，或保留原有录入工具；不要让表单把笔记写到另一套目录。

## 接入资料与成果

按用户当前材料选择 [资料接入](references/materials.md) 中相应流程，先做少量真实样本，再扩大范围。将原始记录、主题入口、项目和成果卡连起来，同时留下“为什么收藏、什么任务用得上”的描述。

默认对大型工程、视频采用稳定原位索引和轻量预览，临时小附件保存一份持久副本。网页正文、课程转写、聊天正文是否可读，分别以实际工具结果为准；缺失部分明确待补。不得编造已经读过的正文、原片时间码、费用或采用状态。

搭建请求本身不等于授权清空旧资料、批量转写全部课程或公开私有内容。清理依赖精确文件范围与已有授权；没有足够依据时交付具体候选和影响说明，不执行删除。

## 验收与交付

按 [验收](references/acceptance.md) 做一次“录入 → 归纳 → 检索 → 打开来源”的检查。有真实材料时验证一条真实链；只有种子库时标明演示，不能把虚构课程的时间当作真实检索结果。

交付说明包括：库的位置与首页、建成的模块、一次可复现的检索结果、实际检查范围，以及仍需配置的事项。记录在库内的“搭建说明”中，给用户两条可以立即尝试的自然语言请求。

不宣称持续后台整理、全聊天自动读取或安装即完成批量转写。后续单次记录与检索按库内规则执行，需要成体系调整时再使用本 skill。
